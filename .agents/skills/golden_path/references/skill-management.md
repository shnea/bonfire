# 스킬 연결 절차

**필요시 읽는다.** 스킬 추가·변경·중지·제거 요청에 적용한다. 일반 개발 작업에서는 연결 목록의 조건에 해당하는 부분만 참고한다.


추가 스킬은 세부 작업 방법을 제공한다. workflow는 작업 절차를, golden_path는 적용 조건과 프로젝트 기준을 계속 관리한다. 추가 스킬의 본문을 이 두 스킬에 복사하거나 추가할 때마다 workflow를 전면 수정하지 않는다.

### 추가 요청을 받았을 때

1. **실제 대상을 확인한다.** 사용자가 준 경로·저장소·파일을 우선 확인한다. 같은 이름·별칭으로 이미 연결돼 있으면 중복 설치하지 않는다. 이름만으로 대상을 특정할 수 없으면 출처를 확인하고, 임의로 같은 이름의 다른 스킬을 가져오지 않는다. 예시나 구조 검토 요청만으로 설치하지 않는다.
2. **내용과 필요한 자원을 읽는다.** SKILL.md의 실제 name·description·본문, 적용 조건, 제외 범위, 참조 파일·스크립트·실행 의존성을 확인한다. 별칭과 실제 스킬 이름이 다르면 모두 기록한다.
3. **프로젝트 안에 보관한다.** 실제 추가가 요청된 경우 `.agents/skills/<폴더명>/`에 SKILL.md와 필요한 참조·자원을 함께 둔다. 원본 출처·버전 또는 커밋·라이선스 정보를 보존한다. 버전이 없으면 확인 가능한 파일 해시 등으로 식별하고 지어내지 않는다. 개인 PC 절대 경로를 프로젝트의 필수 경로로 삼지 않는다.
4. **역할을 연결한다.** [추가 스킬 연결](skills.md)에 실제 이름·별칭, 프로젝트 상대 경로, 출처·의존성·확인 상태를 한 번 등록한다. 그 스킬의 내용을 `항상 참고해야 하는 부분`과 `필요시 적용되는 부분`에 필요한 만큼 연결하고 참조할 파일·절, 역할·제외 범위·협업 관계를 적는다. 필요시 적용에는 `조건 일치` 또는 `명시 요청`과 구체적인 조건을 적는다. 사용자 지정이 있으면 우선하고, 위임됐다면 실제 본문을 근거로 나누고 이유를 남긴다. 전체 본문을 이유 없이 항상 참고로 확대하지 않는다.
5. **사용할 준비를 확인한다.** 파일과 내부 참조, 실제 필요한 실행 도구의 준비 여부를 확인한다. 대표 적용 사례와 비적용 사례를 점검하고, 실행 검증 여부를 구분해 기록한다. 준비가 확인되면 `사용`, 필요한 조건이 빠지면 `준비 중`으로 둔다. 설치만으로 외부 계정 연결·유료 서비스 도입·실제 배포까지 수행하지 않는다.

### 연결 정보의 최소 항목

- **이름과 별칭:** 사용자가 부르는 이름과 SKILL.md의 실제 name.
- **프로젝트 상대 경로와 출처:** 스킬 파일 위치, 원본·버전 식별. 경로 기준은 항상 프로젝트 루트.
- **상태:** `준비 중` / `사용` / `중지`. 폴더 존재와 현재 사용 여부를 구분한다.
- **참고할 부분:** 실제 파일 경로와 제목·절 이름. 필요한 선행 지침도 연결한다. 처음 추가할 때 본문을 확인한 뒤 나누며, 제목을 지어내거나 문맥을 잘라 필수 조건을 누락하지 않는다.
- **연결 영역:** `항상 참고해야 하는 부분` / `필요시 적용되는 부분`. 같은 스킬의 서로 다른 부분을 양쪽에 연결할 수 있다. 전자는 기본 판단 원칙을, 후자는 조건이 맞을 때 수행할 절차를 담는다.
- **적용 범위:** 실제로 어떤 작업에 영향을 주는지, 어떤 경우는 제외하는지. 항상 참고하는 부분에도 범위를 기록한다.
- **필요시 적용 조건:** `조건 일치` / `명시 요청` 중 하나와 구체적인 조건. 스킬 자체의 명시 호출 제한을 임의로 확대하지 않는다.
- **역할과 협업:** 해당 스킬이 책임질 결과, 겹치는 스킬이 있으면 주도·보조 관계.
- **프로젝트 예외:** 원본과 다르게 적용할 부분이 있다면 이유와 범위. 원본 본문을 몰래 바꾸지 않고 연결 기준에 명시한다.
- **의존성과 확인:** 필요한 도구·자료, 파일 및 적용 사례 점검 결과, 실제 실행 여부와 남은 제약.

### 사용할 때

- 상태를 먼저 확인한다. `준비 중`·`중지` 스킬은 어느 영역에 연결돼 있어도 적용하지 않는다. 사용자가 중지된 스킬을 이번에 사용하라고 명시하면 이번 작업의 예외인지 지속적인 재개인지 구분해서 기록한다.
- `항상 참고해야 하는 부분`은 작업 시작 시 실제 파일의 지정 부분을 읽고 기본 판단에 반영한다. 구체적인 행동은 적용 범위에 맞춘다. 예를 들어 코딩 원칙을 항상 참고해도 번역 요청에 코드 리뷰를 추가하지 않는다.
- `필요시 적용되는 부분`은 목록의 이름·조건·역할을 먼저 보고 필요할 때 지정된 부분과 선행 맥락을 읽는다. 조건 일치는 해당 작업 상황을 근거로 판단하며, 명시 요청은 해당 스킬이나 연결된 특별 지시가 요청에 있을 때만 성립한다.
- 같은 작업에서 읽은 변경 없는 본문을 매 응답·명령마다 다시 읽지 않는다. 새 작업·세션이나 관련 본문·연결 규칙의 변경 시 다시 확인한다.
- 이번만 사용하라는 요청으로 항상 참고하는 부분을 늘리지 않는다. 지속적으로 쓰라는 요청을 받으면 연결된 부분·조건을 갱신한다. 스킬의 출처·상태는 한 번 등록하고, 부분별 연결과 절차 실행은 중복하지 않는다.
- 스킬의 선언된 적용 조건과 호출 제한을 확인한다. 실제 설정이 명시 요청 전용이면 항상 참고하려는 의도와의 차이를 알리고 해결 전까지 준비 중으로 둔다. 사용자 요청 없이 원본 제한을 없애지 않는다.
- 사용자 요청과 프로젝트에서 합의한 기준·예외를 우선하며, 그 범위 안에서 원본 스킬의 상세 절차를 따른다. 상위 실행 환경의 지침·권한 제한도 유지한다.
- 겹치는 역할은 주도·보조를 정해 한 번 수행한다. 조정할 수 없는 요구 충돌만 질문한다.
- 항상 참고하는 부분을 더 높은 지침 우선순위로 해석하지 않는다. 프로젝트 기준·예외와 지정된 주도·보조 관계로 충돌을 해결한다.
- 필수 파일·도구가 없으면 사용했다고 보고하지 않는다. 가능한 일반 작업은 진행하고, 그 스킬이 필수인 검증은 미실행으로 남긴다.
- 연결 정보는 에이전트가 읽고 적용하는 지침이다. 모든 도구에서 자동으로 강제되는 실행 장치가 아니다. 다른 도구에서 시작 안내를 읽는지와 실제 선택 동작은 별도로 확인한다.

### 바꾸거나 빼 달라는 요청을 받았을 때

- 범위 변경은 연결 정보와 영향을 받는 기준만 갱신한다. 추가할 때마다 workflow에 스킬별 분기를 늘리지 않는다.
- 일시 중지는 `중지`로 기록하고 이후 작업에서 선택하지 않는다. 파일은 유지할 수 있다. 이 기록이 도구 자체의 자동 탐색을 비활성화하는 설정이라고 주장하지 않는다.
- 제거는 연결 정보·관련 예외·참조를 정리한다. 파일 삭제는 요청 범위에 포함된 경우에만 한다.
- 버전 변경은 출처·식별 정보·달라진 적용 조건과 의존성을 확인한다. 자동 업데이트로 프로젝트별 예외를 덮어쓰지 않는다.

실제 연결 기록은 [추가 스킬 연결](skills.md)에 유지한다.
