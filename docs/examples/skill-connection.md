# 스킬 연결 예시

설명용 참고 자료다. 스킬 연결 작업마다 읽는 필수 지침이 아니다. 실제 연결은 [스킬 연결 절차](../../skills/golden_path/references/skill-management.md)를 따른다.

## 설명용 예시: 구현 단순화 스킬 연결

구현을 단순하게 유지하는 원칙과 상세 절차를 가진 스킬을 가정한 설명용 예시다. 실제 연결할 때는 해당 스킬의 본문과 적용 조건을 확인한다.

1. 추가할 스킬의 실제 파일·출처·name과 적용 범위를 확인한다.
2. 본문에서 단순한 구현과 기존 코드 재사용을 우선한다는 지침을 확인한 경우, 설계·구현·리팩터링·코드 리뷰 중 본문과 프로젝트 요구에 맞는 범위를 연결한다.
3. 사용자와 실제 본문이 허용하는 경우, 기존 코드 재사용·단순한 구현 선택 등의 기본 원칙을 `항상 참고해야 하는 부분`에 연결하고 적용 범위를 `코딩 작업`으로 적는다.
4. 본문에 별도의 상세 절차나 강도 선택이 있다면 `필요시 적용되는 부분`에 실제 절 위치와 적용 조건을 연결한다. 예를 들어 특별한 단순화 요청에 대응하는 절차는 그 요청이 있을 때 적용한다. 본문에 없는 절차는 만들어 넣지 않는다.
5. workflow는 기본 원칙을 작업 시작에 읽어 유지하고, 필요시 부분은 상황이나 특별 지시가 생길 때 확인한다. 코딩에서는 기존 코드·표준 기능을 먼저 검토하되 코딩과 무관한 요청에 구현 절차를 추가하지 않는다.
6. 단순함을 이유로 요구사항·정확성·보안·접근성·필요한 검증을 생략하지 않는다. 추가 스킬이 기존 공통 원칙을 보완하므로 동일한 분석·검증을 두 번 수행하지 않는다.

예시 점검: `목록 검색 기능 구현`에서는 항상 참고할 코딩 원칙을 적용, `특정 상세 절차 요청`에는 연결된 필요시 부분을 추가 확인, `한국어 인사말 번역`에는 코딩 절차를 추가하지 않음, `중지 상태에서 기능 구현`에는 해당 스킬을 적용하지 않음. 실제 적용 시에는 해당 스킬의 연결 조건에 맞춰 동작을 검증한다.

필요시 부분의 다른 예시: 화면 점검 절차는 `조건 일치 · UI 변경 시`, 정밀 검토 절차는 `명시 요청 · 정밀 검토를 요청했을 때`처럼 적을 수 있다.
