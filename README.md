# Bonfire

AI와 개발하며 쌓아온 스킬과 지침은 작업의 품질을 높여주지만, 개인 환경에 흩어져 있으면 새로운 환경에서 같은 기준을 이어가기 어렵습니다.

Bonfire는 이러한 기준을 프로젝트와 함께 관리하기 위해 만들었습니다. 필요한 스킬과 작업 절차, 요구사항과 결정들을 프로젝트 안에 담아, 개발 환경이나 에이전트가 바뀌어도 같은 맥락과 기준으로 작업을 이어가는 것이 목표입니다.

이름은 소울 시리즈의 ‘화톳불’에서 가져왔습니다. 여정 중 화톳불에서 정비하고 다시 출발하듯, 언제든 돌아와 프로젝트의 기준을 확인하고 다음 작업을 준비하는 거점이 되고자 합니다.

## 두 기본 스킬

**workflow와 golden_path, 두 기본 스킬로 시작하는 프로젝트 템플릿입니다.** 사용자와 대화하면서 범용 항목을 추가·삭제·수정하고 예외를 정해 해당 프로젝트의 기준으로 발전시킵니다. 필요한 전문 스킬도 나중에 연결할 수 있습니다.

| 스킬 | 역할 |
| --- | --- |
| [workflow](.agents/skills/workflow/SKILL.md) | 요구를 듣고 기준을 갱신하며 구현·검증·인계하는 작업 절차 |
| [golden_path](.agents/skills/golden_path/SKILL.md) | 현재 프로젝트의 요구사항·선택·제약·예외와 참고할 기준 관리 |

workflow가 golden_path의 현재 기준을 적용하고, 새 요구가 생기면 관련 기준을 갱신합니다.

## 항상 확인하는 핵심과 필요한 영역 구분

프로젝트 기준은 핵심·영역·스킬 연결·결정 이력으로 나누어 관리합니다. 작업에 필요한 문서만 골라 읽을 수 있습니다.

```text
AGENTS.md
docs/examples/skill-connection.md  설명용 스킬 연결 사례
.agents/skills/
├─ workflow/SKILL.md
└─ golden_path/
   ├─ SKILL.md
   └─ references/
      ├─ core.md                 항상 확인할 현재 핵심 기준
      ├─ project-rules.md        관련 영역을 찾는 짧은 색인
      ├─ domains/               필요할 때 읽는 14개 영역별 파일
      ├─ skills.md               추가 스킬 상태·부분별 연결
      ├─ skill-management.md     스킬 추가·변경 때 읽는 절차
      ├─ transfer.md             기준 내보내기·가져오기 절차
      └─ decisions.md            과거 이유가 필요할 때 읽는 이력
```

| 자료 | 읽는 범위 |
| --- | --- |
| [core.md](.agents/skills/golden_path/references/core.md) | 작업 시작에 현재 목적·범위·핵심 결정·제약 확인 |
| [project-rules.md](.agents/skills/golden_path/references/project-rules.md) | 영역 선택에 사용. 상세 기준은 관련 영역 파일만 읽음 |
| [skills.md](.agents/skills/golden_path/references/skills.md) | 상태·조건 확인. 항상 참고할 부분과 필요시 부분을 구분 |
| [skill-management.md](.agents/skills/golden_path/references/skill-management.md) | 스킬 추가·변경·중지·제거를 요청받았을 때만 읽음 |
| [decisions.md](.agents/skills/golden_path/references/decisions.md) | 과거 결정의 이유가 필요할 때 해당 내용만 읽음 |
| [transfer.md](.agents/skills/golden_path/references/transfer.md) | 프로젝트 기준을 내보내거나 가져올 때만 읽음 |

시작 안내는 진입점, workflow는 작업 절차, golden_path는 읽기·갱신 규칙을 맡습니다. 현재 핵심 기준에는 프로젝트의 중요한 결론과 상세 위치만 남깁니다. 세부 규칙은 책임 영역 한곳에 두고 다른 영역에서는 연결합니다. 이력은 현재 기준을 대체하지 않습니다.

## 필요한 영역 선택

범용 목록은 목적·기능·제약·기술·구조·데이터·보안·UI·연동·성능·검증·Git·운영·문서의 14개 분야, 67개 초기 항목으로 구성됩니다. 전체 항목은 [영역별 색인](.agents/skills/golden_path/references/project-rules.md)에서 확인할 수 있습니다.

- 처음 프로젝트를 정의할 때는 색인 전체의 적용 여부를 살펴보고 필요한 영역부터 구체화합니다.
- 개발 중에는 핵심과 현재 작업·변경 영향에 관련된 영역만 확인합니다.
- UI의 삭제 동작을 바꾸면 UI뿐 아니라 데이터·권한·검증 기준도 확인합니다.
- 공통 정의 항목은 처음 정리할 주제라는 의미입니다. 매번 전체 본문을 읽으라는 뜻이 아닙니다.
- 앞으로 필요할 선택 항목과 작성할 자리는 유지합니다. 현재 사용하지 않는다는 이유로 삭제하지 않습니다. 미결정은 공란·미정·보류로, 적용 대상이 아니면 해당 없음과 이유를 남깁니다.
- 항목을 마련해두는 것과 실제 기능 구현·절차 실행은 구분합니다. 중복 설명과 반복 절차는 정리하되 선택 항목의 범위는 보존합니다.

## 사용 흐름

```text
원본 템플릿을 새 프로젝트로 복사
  → 사용자와 목적·핵심 기능·범위를 대화
  → 관련 기준을 함께 결정하고 맡겨진 부분은 AI가 판단
  → 다음 구현에 필요한 정의가 준비되면 개발·검증
  → 요구가 바뀌면 핵심과 관련 영역을 갱신
```

언어·DB·Docker·배포 업체는 고정하지 않습니다. 모든 항목을 채워야 개발할 수 있는 것도 아닙니다. 원본은 유지하고 프로젝트별 사본에서 기준을 발전시킵니다.

## 프로젝트 기준 내보내기·가져오기

지금까지 정리한 프로젝트 기준을 문서 묶음으로 내보내고, 새 환경의 golden_path에서 이어서 관리할 수 있습니다. 스킬 지침을 읽는 에이전트가 파일 생성·검사·병합을 수행합니다.

### 내보내기

프로젝트에서 다음처럼 요청합니다.

```text
지금까지 정리한 프로젝트 기준을 내보내줘. 코드와 실행 명령은 제외하고,
다른 환경의 golden_path에서 이어서 사용할 수 있게 만들어줘.
```

기본 산출물은 `exports/bonfire-<프로젝트명>-<날짜와 시각>/` 아래 Markdown 문서 묶음입니다. 저장 위치를 지정하거나 ZIP으로 요청할 수도 있습니다.

| 포함하는 내용 | 제외하는 내용 |
| --- | --- |
| 목적·요구사항·기술 선택·제약·예외·결정 이유 | 소스 코드·코드 예제·실행 명령·스크립트·설정 파일 |
| 확정·미정·보류·해당 없음과 빈 작성 자리 | 빌드 산출물·로그·비밀값 |
| 기존 영역과 사용자 추가 영역, 필요한 참조 문서 | AGENTS.md·workflow·스킬 본문·실행 자원·관리 절차 |
| 추가 스킬의 출처·역할·적용 조건·원본 상태 | 추가 스킬 설치·활성화 권한 |

golden_path 폴더만 통째로 복사하지 않고, 기준을 이해하는 데 필요한 참조 내용도 포함합니다. Markdown 안의 코드·명령은 설명으로 바꾸며 변환 사실을 기록합니다. 원본은 유지하고 문서 간 링크는 묶음 안에서 이어지도록 조정합니다. 가져오기에 필요한 내용은 요약으로 축약하지 않습니다.

```text
BONFIRE-EXPORT.md       형식 버전·출처·파일 목록·제외/변환·누락
context/
  core.md              현재 핵심 기준
  project-rules.md     영역 색인
  domains/             영역별 기준
  decisions.md         결정 이유와 이력
  skills.md            추가 스킬 연결 정보
  supporting/          필요할 때 포함하는 참조 문서
```

### 가져오기

기본 Bonfire 구성을 준비한 대상 프로젝트에서 묶음의 경로와 용도를 함께 지정합니다.

```text
../project-context/의 기준 묶음을 이 프로젝트로 가져와줘.
같은 프로젝트를 새 환경에서 이어가는 것이니 기존 결정과 상태를 복원해줘.
```

```text
../project-context/의 기준 묶음을 새 프로젝트의 참고용으로 가져와줘.
기존 결정은 제안으로 두고, 이 프로젝트에서 채택한 것만 확정해줘.
```

| 용도 | 처리 방식 |
| --- | --- |
| 같은 프로젝트 이어가기 | 결정·상태·이유를 복원하고 새 환경의 경로·연동·검증 상태는 별도로 확인 |
| 다른 프로젝트의 출발점 | 원본을 참고 자료로 보존하고 재사용 후보를 제안으로 등록. 대상의 기존 확정 기준 유지 |

기존 기준은 먼저 백업하고 항목별로 병합합니다. 충돌하는 기준을 임의로 덮어쓰지 않으며, 같은 내용을 다시 가져와도 중복 추가하지 않습니다. 추가 스킬은 `준비 중`으로 가져온 뒤 대상에 실제로 있는 연결만 확인해서 사용합니다.

이 묶음에는 코드와 스킬 실행 지침이 없습니다. 대상에 Bonfire가 없다면 이 템플릿이나 [설치용 Bonfire 스킬](https://github.com/shnea/bonfire_skill)로 기본 구성을 먼저 마련합니다. 기준 복원만으로 제품이나 실행 환경이 복원되지는 않습니다. 접근할 수 없는 참조 등 누락이 있으면 내보내기 목록과 가져오기 결과에 표시합니다.

원본의 `golden_path`와 설치용 스킬의 `golden-path`는 동일한 **문서 묶음 형식 v1**을 사용합니다. 자세한 포함 범위·검사·병합 규칙은 [내보내기·가져오기 절차](.agents/skills/golden_path/references/transfer.md)에 있습니다.

## 전문 스킬 연결

실제 스킬의 본문·참조를 프로젝트에 보관하고 상태·출처는 한 번 등록합니다. 같은 스킬의 기본 원칙과 상세 절차를 아래 두 영역에 나눌 수 있습니다.

- **항상 참고해야 하는 부분:** 작업 시작 시 읽고 기본 판단에 반영할 원칙
- **필요시 적용되는 부분:** 특정 상황이나 특별 지시에 맞을 때 읽고 적용할 절차

workflow는 연결된 부분·조건을 읽어 적용합니다. 전문 스킬을 추가할 때마다 workflow를 다시 작성하지 않습니다. 중지 상태면 양쪽 모두 적용하지 않습니다.

[스킬 연결 예시](docs/examples/skill-connection.md)는 기본 원칙과 상세 절차를 나누어 연결하는 방법을 보여주는 설명용 예시입니다.

## 버전과 사용 환경

현재 버전은 **v1**입니다.

사용하는 에이전트가 프로젝트의 `AGENTS.md`와 스킬 지침을 읽도록 설정하세요. 자동 인식 여부는 도구별로 확인하고, 필요한 경우 시작 설정에서 `AGENTS.md`를 읽도록 연결합니다.
