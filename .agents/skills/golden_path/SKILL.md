# golden_path

## 필요한 기준 읽기

| 자료 | 확인 시점 |
| --- | --- |
| [core.md](references/core.md) | 작업 시작에 현재 핵심 결정·제약 확인 |
| [project-rules.md](references/project-rules.md) | 관련 영역을 찾고 작업·변경 영향에 필요한 파일만 읽음 |
| [skills.md](references/skills.md) | 작업 시작 시 등록 상태·조건을 확인하고, 사용 중인 스킬의 항상 참고할 부분을 읽음. 필요시 부분은 상황·명시 요청이 맞을 때 읽음 |
| [skill-management.md](references/skill-management.md) | 스킬 추가·변경·중지·제거 요청일 때만 읽음 |
| [decisions.md](references/decisions.md) | 과거 결정의 이유가 필요할 때 해당 항목만 읽음 |

모든 파일을 일괄 읽지 않는다. 같은 작업에서 읽은 변경 없는 내용은 반복하지 않는다. 처음 프로젝트를 정의할 때는 영역 색인 전체의 적용 여부를 살펴본다. 영역의 공통 정의 항목 표시는 매 작업마다 읽으라는 뜻이 아니다. 예를 들어 UI의 삭제 동작은 데이터·권한·검증 기준도 확인한다.

## 대화로 기준 갱신

- 범용 템플릿은 앞으로 사용할 선택 항목과 작성할 자리를 포함한다. 지금 사용하지 않는다는 이유로 항목·영역·확장 자리를 삭제하지 않는다. 향후 필요가 예상되는 항목은 추가하고, 정하지 못한 내용은 공란·미정·보류로 유지한다.
- 항목을 보존하는 것과 지금 기능을 구현하거나 절차를 실행하는 것은 구분한다. 해당 없음도 항목과 판단 근거를 남긴다. 정리는 중복 설명·반복 절차를 통합하는 데 집중하며, 항목 자체의 삭제는 사용자의 명시적인 삭제 요청이나 삭제하기로 합의한 범위에서 한다.
- 사용자 지정은 유지한다. 빈칸·미정·AI 판단은 필요한 시점에 목적·제약·기존 코드에 근거해 결정한다. 제안·가정은 확정값과 구분하고, 보류는 필요해질 때 다루며 해당 없음은 적용하지 않는다.
- 에이전트의 선호만으로 확정된 선택을 다시 고르지 않는다. 새 요청·제약·검증 결과로 바뀌면 관련 기준·구현·검증을 함께 갱신한다.

## 기록 위치

- 새 주제는 가장 가까운 영역에 추가한다. 독립된 영역으로 나누면 영역 파일과 project-rules 색인을 함께 갱신한다.
- 현재 중요한 결론과 상세 위치는 core에, 세부 규칙은 책임 영역 한곳에 둔다. 다른 영역에서는 링크하고 문장을 복제하지 않는다.
- 예외는 해당 영역에 대상·조건·대체 기준·이유를 기록한다. 임시 예외에는 해소 조건을 적고 중요한 예외는 core에서 안내한다.
- 중요한 선택·변경·삭제의 이유와 영향만 decisions에 남긴다. 모든 대화·명령을 기록하지 않는다. 문서의 항목 삭제를 실제 코드·데이터 삭제 명령으로 해석하지 않는다.
- 전문 스킬 본문은 원래 파일에 두고, 상태·출처·항상 참고할 부분·필요시 적용할 부분은 skills에 연결한다. 중지·준비 중은 적용하지 않으며, 같은 절차를 중복 수행하지 않는다. 항상 참고한다고 더 높은 우선순위를 갖지는 않는다.
- 실제 실행 명령·검증 상태는 검증 영역에 유지한다. 프로젝트별 결정을 원본에 자동 전파하거나 템플릿 업데이트로 덮어쓰지 않는다.
